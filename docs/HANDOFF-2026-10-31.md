## Priority fixes before production or live deployment

See `review-schedule-i.md` and the agent review findings retained in the task:

1. `cli.run_prompt` loads preferences/keys and can classify using a provider **before** `prepare` rejects this
   player profile. Add an early retail-profile guard before all such calls and before service account/memory sends.
2. A pre-cancelled run can enter `harness.setup`; RestrictedLink does not yet check cancellation on every request.
   Reject pre-cancel before setup, add a session cleanup watchdog, and revoke non-cleanup calls after stop.
3. Wildcard kit imports still request SDK-only exports. Either supply a deliberately compatible lazy export
   design or document/use explicit SDK-free harness imports; do not claim all upstream harness code works.
4. Arbitrary reviewed Python setup/observe/executor/callback code is cooperative and can block indefinitely.
   Native input leases are independently bounded, but Python wall-time is not a process sandbox. A production
   hard-time guarantee requires an isolated owned worker process and exact cleanup tests.
5. Large calibrated mouse turns can exceed 200 counts per request. Add bounded chunking with preflight total
   budget validation or explicitly constrain harnesses; do not silently clamp and claim a successful turn.
6. Add cleanup-on-decision-validation-failure tests and stop immediately on malformed/unoffered model choices.
